# evolve — 1サイクル＝1タスク＝1コミット

このスキルは `docs/ROADMAP.md`（バックログ）から先頭の未着手タスクを1件だけ拾い、実装・テスト・レビュー・記録・コミットまでを1サイクルで完結させる。`/loop 2h /evolve` のように定期実行される想定。**このファイル単体で完結するように書いてある**（会話の前の文脈を覚えている前提を置かない）。

プロジェクトの規約は [CLAUDE.md](../../../CLAUDE.md) を必ず読むこと（ESモジュール禁止・`RallyOne` 名前空間パターン・テストコマンドなど）。

## 0. 事前条件チェック（満たさなければ即終了）

1. `git status --short` で作業ツリーがクリーンであることを確認する。何か残っていたら **絶対に上書き・破棄しない**。中断された前回サイクルの跡かもしれないので、内容を報告して終了する。
2. 現在のブランチが `main` であることを確認する（`git branch --show-current`）。違えば `main` に戻れるか確認し、戻れなければ状況を報告して終了する。
3. `node tests/smoke.mjs` を実行し、**着手前の時点で既に壊れていないか**を確認する。壊れていたら実装せずに報告して終了する（既存の壊れた状態の上に新しい変更を積まない）。

## 1. タスクを選ぶ

`docs/ROADMAP.md` の「未着手」セクションを上から読み、`- [ ]` かつサイズが **`S` または `M`** の最初の項目を選ぶ。

- `L` サイズの項目は **絶対に自動着手しない**。方針が固まっていない／複数サイクルにまたがる大きな仕事だから。見かけたら読み飛ばして次を見る。
- `S`/`M` の項目が1つも無ければ、何もせずに終了する。報告には「バックログに着手可能な項目なし」と明記する（`/loop` を動的モードで呼んでいるなら、この報告を見て呼び出し側がループを止める判断をする）。
- 選んだ項目のタイトルから短い英語スラッグを作る（例:「ネットポストの位置を実測値に合わせる」→ `net-post-position`）。

## 2. ブランチを切る

```sh
git checkout -b evolve/<slug>
```

以降の作業はこのブランチの上だけで行う。**`main` を直接編集しない。**

## 3. 実装する

- 選んだ1項目の範囲だけを実装する。ついでのリファクタや無関係な修正はしない（スコープを広げない）。
- `CLAUDE.md` の規約（ESモジュール禁止、`RallyOne.config` へのマジックナンバー集約、`game.js`/`physics.js`/`scoring.js`/`ai.js` は three.js・DOM に触らない、など）に従う。
- 既存のコードスタイル（コメントは非自明な WHY のみ、日本語コメント、命名パターン）に合わせる。

## 4. テストする

```sh
node tests/smoke.mjs
```

- 通らなければ原因を調べて直す。
- **同じ根本原因で2回失敗したら、そのサイクルは撤退する。** `git checkout main && git branch -D evolve/<slug>` でブランチごと破棄し、`docs/ROADMAP.md` の該当項目はチェックを付けずに残す（末尾に `<!-- evolve: 2026-XX-XX 失敗、理由: ... -->` のような短いコメントを添えてもよい）。無理に不完全な変更をコミットしない。
- UI/描画に関わる変更（`src/scene/*`、`styles/*`、`index.html`）は `node --check` での構文確認に加えて、可能なら headless Chrome か `claude-in-chrome` で実際に開いて目視確認する。`tests/smoke.mjs` はロジック層しか見ていない。

## 5. セルフレビューする

`code-review` skill を、このサイクルで作った差分（`git diff main...HEAD`）に対して low〜medium の effort で呼ぶ。明らかな問題（バグ、スコープ逸脱、規約違反）が見つかったら直してから次に進む。深刻な問題が解決できなければ手順4と同じ撤退ルールに従う。

## 6. 記録する

1. 必要なら `README.md` を更新する（操作方法・構成が変わった場合のみ）。
2. `docs/ROADMAP.md` から該当項目を削除し、`docs/roadmap-done.md` の先頭（ヘッダー直後）に、その書式に従って追記する。
3. `docs/roadmap-done.md` の記述に基づき、依存する後続タスクがあれば `docs/ROADMAP.md` の記述を軽く更新してよい（例：スピンの方針が決まったら該当行の注記を更新する）。ただし新しいタスクを勝手に増やしすぎない。

## 7. コミットする（プッシュはしない）

```sh
git add -A
git commit -m "<what/why を1〜2文、日本語>"
```

- 1サイクル＝1コミット。
- **push はしない。** リモートの有無に関わらず、コミットはこのローカルブランチに留める。プッシュはユーザー自身の判断に委ねる。
- コミット後、`git checkout main` でメインへ戻り、作業ツリーをクリーンな状態にして終了する（次のサイクルの事前条件チェックが通るように）。

## 8. 報告する

最後に短く報告する：

- 拾った項目とサイズ
- 作ったブランチ名
- テスト結果（PASS / 撤退した場合はその理由）
- コミットしたかどうか、コミットハッシュ
- バックログに `S`/`M` の項目がまだ残っているか（残っていなければ次のループで拾われる旨、残っていなければ空である旨を明記）

## やってはいけないこと

- `main` ブランチを直接編集する
- `push`・`push --force`・履歴の書き換え
- テストが落ちたまま、あるいは撤退ルールに反してコミットする
- `L` サイズの項目に自動着手する
- 1サイクルで複数のバックログ項目に手を出す
- バックログが空なのに存在しない作業をでっち上げる
