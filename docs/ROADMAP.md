# ROADMAP

`/evolve` skill（`.claude/skills/evolve/SKILL.md`）がこのファイルを読んで、1サイクルにつき1項目だけ拾って実装する。
完了した項目は [docs/roadmap-done.md](./roadmap-done.md) に移す。

## 書式

```
- [ ] <サイズ> <タイトル> — <補足・受け入れ条件>
```

- **サイズ**は `S`（1サイクルで確実に終わる小さな修正）／`M`（1サイクルで終わるが設計判断を伴う）／`L`（複数サイクルにまたがる、または着手前に方針を相談すべき大きな機能）。
- `/evolve` は **`S` と `M` だけを自動で拾う**。`L` は拾わない（人間がサイズを分解して `S`/`M` に落とすか、方針を決めてから着手する）。
- 優先度は上から順。追加するときは狙う位置に挿入する（末尾ではなく）。

## 未着手

- [ ] M CPU に「プレースタイル」を持たせる — `CPU_LEVELS` と同じ `{cpu:{...}, player:{...}}` の上書きプリセット構造で、強さ（Easy/Normal/Hard）とは直交する性格を足す。サーブ&ボレーヤー（サーブ後にネットへ詰める・`NET_Z` 圏内での勝負を好む）、守備型リトリーバー（`CPU_CHASE` 高め・`OUT_*` 低め・ロブ多め・浅い球は返すだけ）、アグレッシブベースライナー（`AIM_X` 広い・`SHOT_T` 短い・`OUT_*` 高い）。受け入れ条件：同じ強さでもスタイルによってラリーの平均本数・ロブ率・ネットへ出る頻度が有意に変わること。既存の Easy/Normal/Hard の値は変えず、スタイル無指定なら現状と完全に一致すること。「ネットに出た相手への攻め手の多様化」と噛み合わせること。

- [ ] M ポイントが決まった後にリプレイを流す — 直近3〜4秒ぶんのボールと選手4人の位置をリングバッファに録っておき、ポイント終了後にローアングルのカメラで再生する（物理は再計算せず座標を再生するだけ）。今も `trail`（直近1打の軌跡）をポイント後に見せているので、その発展形。受け入れ条件：ゲームロジック（`game.js`）に一切触れずに実現すること（記録も再生も表示側で完結）、再生中に次のポイントへ進む処理が止まらないこと（あるいは再生ぶんだけ待つ）、スキップできること。

- [ ] M スタミナを入れる — 長いラリーで消耗し、`PLAYER.SPEED`／`CPU_CHASE` と溜まる速さ（`CHARGE.MAX_TIME` 相当）が落ちる。ドロップとロブが「相手を走らせる道具」として意味を持つようにするのが狙い。ポイント間で少し回復する。受け入れ条件：効き幅は控えめに（走り回った直後でも操作不能に感じない程度）、HUDに残量が見えること、人間とCPU/AIの両方に同じルールで効くこと。やりすぎると理不尽になるので、実測でラリー20本後の速度低下率を数字で示して調整すること。

- [ ] S 観客の歓声を入れる — `audio.js`（Web Audio）に、ポイントが決まったときのざわめき／歓声を足す。ラリーの長さと決まり方（エース・ウィナー・凡ミス）で音量と長さを変える。受け入れ条件：既存の効果音とぶつからない音量バランスであること、長いラリーの末のウィナーが一番盛り上がること、鳴らす条件・音量は `config.js` に集約すること。

- [ ] S 試合開始時にサーブ／レシーブを選べるようにする — 実際の試合と同じくトス（コイントス）から始め、勝った側がサーブかレシーブかを選ぶ。人間が勝ったらスタート画面で選択、CPUが勝ったら自動で選ぶ（サーブを選ぶ確率を高めに）。受け入れ条件：選択に応じて第1ゲームのサーバーが正しく決まり、以降のゲームごとの交代（ダブルスの `serverPartner` の巡りも含む）が現行どおり続くこと。`scoring.js` は純ロジックのままにすること。
