# ROADMAP

`/evolve` skill（`.claude/skills/evolve/SKILL.md`）がこのファイルを読んで、1サイクルにつき1項目だけ拾って実装する。
完了した項目は [docs/roadmap-done.md](./roadmap-done.md) に移す。

## 書式

```
- [ ] <サイズ> <タイトル> — <補足・受け入れ条件>
```

- **サイズ**は `S`（1サイクルで確実に終わる小さな修正）／`M`（1サイクルで終わるが設計判断を伴う）／`L`（複数サイクルにまたがる、または着手前に方針を相談すべき大きな機能）。
- `/evolve` は **`S` と `M` だけを自動で拾う**。`L` は拾わない（人間がサイズを分解して `S`/`M` に落とすか、方針を決めてから着手する）。
- 優先度は上から順。追加するときは狙う位置に挿入する（末尾ではなく）。

## 未着手

- [ ] M 外方向に強いサーブを打つとフォールトになりやすい問題を調整する — ワイドを強打で狙うと不自然にネット／アウトになりやすい体感がある。`SERVE.CLEARANCE`・`CHARGE_T`・`AIM_WIDE_MIN/MAX` あたりのバランスを見直し、強いワイドサーブが実用的な成功率で入るようにする。上のフォールト実装が先に入っていること（挙動を確認しながら調整するため）。
- [ ] S エース／フォールト／ダブルフォルトのスタッツをHUDに表示する — 上のフォールト実装が前提。ポイント間のコール表示や簡単なスコアボード拡張で、ラリーなしで決まったポイント（エース／サービスウィナー／ダブルフォルト）が分かるようにする。
- [ ] S 効果音のバリエーションを増やす — 現状ヒット音・バウンド音などが毎回同じで単調。`audio.js` に複数バリエーションを用意し、打球のたびにランダムで選ぶ（音程/音色を少し振る程度でよい、新規サンプルは追加しない＝Web Audio のみで完結させる）。
- [ ] M 6-6のタイブレークを実装する — 現状 `RULES`（`GAME_POINTS`/`SET_GAMES`/`MARGIN`）はアドバンテージセット（2ゲーム差がつくまで続行）のみで、6-6でのタイブレークがない。`scoring.js` にタイブレーク中のポイント計算（7点先取・2点差、ポイントごとにサーバー交代）を追加し、`game.js`/`hud.js` 側でタイブレーク中の表示・サーブ交代タイミングを合わせる。
- [ ] M CPUの難易度をスタート画面で選べるようにする — 現状 `CPU.*`（反応速度・狙いの精度・ミス確率など）は固定値。Easy/Normal/Hard程度の3段階を `config.js` に用意し、スタート画面で選択、選んだ段階に応じて `CPU` の値を切り替える。
- [ ] L ボールにスピン（トップスピン／スライス／フラット）を実装する — 詳細未設計。重力(`PHYSICS.GRAVITY`)とボール半径(`PHYSICS.BALL_R`)が意図的に非現実値（アーケード寄り）になっているため、マグヌス力を実式で足すと効果が見た目に乗りにくい可能性がある。着手前に「アーケードのまま感覚チューニングするか」「重力・ボールサイズを実測寄りに戻すか」を人間と相談すること（2026-08-17の会話で論点として提示済み）。→人間と相談して、アーケードのまま感覚チューニングすることで合意。

- [ ] L 風（弱いランダムな横風）を実装する — スピンの実装方針（力の掛け方の設計）が固まってから着手した方が、物理モデルの一貫性を保ちやすい。
