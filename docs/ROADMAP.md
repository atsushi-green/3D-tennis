# ROADMAP

`/evolve` skill（`.claude/skills/evolve/SKILL.md`）がこのファイルを読んで、1サイクルにつき1項目だけ拾って実装する。
完了した項目は [docs/roadmap-done.md](./roadmap-done.md) に移す。

## 書式

```
- [ ] <サイズ> <タイトル> — <補足・受け入れ条件>
```

- **サイズ**は `S`（1サイクルで確実に終わる小さな修正）／`M`（1サイクルで終わるが設計判断を伴う）／`L`（複数サイクルにまたがる、または着手前に方針を相談すべき大きな機能）。
- `/evolve` は **`S` と `M` だけを自動で拾う**。`L` は拾わない（人間がサイズを分解して `S`/`M` に落とすか、方針を決めてから着手する）。
- 優先度は上から順。追加するときは狙う位置に挿入する（末尾ではなく）。

## 未着手

### バグ（実測で再現を確認したもの）

- [ ] S `tests/smoke.mjs` の「full charge should land clearly deeper」が約1%の確率で落ちる — 溜めなし／フル溜めの着地点を1本ずつ引いて `full > tap + 4.5` を見ているが、深さのばらつき（`SHOT.DRIVE_Z_SPREAD`）で差が最小 4.36m まで詰まる（実測：20000回で 0.9%）。ツイーナーの調整とは無関係な既存の不安定さ。何本か打った中央値で比べるか、この1件だけ `Math.random` を固定する。

- [ ] S `tests/smoke.mjs` に他にも数%で落ちるテストがある — 「and as fast as a fully charged normal shot」（ライジングの球速。15本の中央値どうしの比較で `rising >= full * 0.97` を割る。実測 25回中1回）と「doubles: timers do not leak: 2」（30回中1回、変更前のコードでも再現）。上の項目と同じく、本数を増やすか `Math.random` を固定する。

- [ ] M 地面すれすれ（打点 0.2m 以下）で捉えたフル溜めのグラウンドストロークが必ずネットに掛かる — `hit()` は打点が `SHOT.SOLVE_MIN_Y`（0.5m）より低いと 0.5m から打ったとして `solveShot()` で初速を解くが、球そのものは実際の打点から飛ぶので、解いた弾道より (0.5 − 打点) だけ低く飛ぶ。既定のネット余裕 0.30m からこの差を引くと、打点 0.2m 以下では余裕がボールの半径（0.11m）を割る（実測：ベースライン上・弾んだ直後の球で、打点 0.12m／0.2m のフル溜めは 40本中40本ネット、0.3m 以上は0本。人間役ボットの実戦でもフル溜めの2〜7%がネット）。必殺技ライジングだけは `specialShot()` でこの差を余裕に足し戻している。直すなら `from.y` を実際の打点にする（弾道が全体に少し山なりになるので球速・深さの実測を取り直す）。「低い打点から強打するとネットしやすい」という手触りとして一部残すかは要判断。

### 表示の不足

- [ ] S Hard / Extreme の AI の必殺技の残り回数が画面に出ない — `hud.setSpecialUses()` は人間の `game.specialUses` しか見ておらず、AI が技ごとに独立した回数を持っている（`actor.specialUses`）ことが分からない。相手が鷹の目を使い切ったかどうかは駆け引きの材料になるので、スコアボード側に相手ぶんも小さく出す。**Extreme では技ごとに複数回（`CPU.SPECIAL_USES`）持つので、残り本数の表示価値はさらに上がった**（人間側の表示は `SPECIAL.USES_PER_GAME > 1` のときだけ `×N` を出す作りなので、同じ考え方で足せる）。

### 追加したい機能

- [ ] M 音量調整とミュート — 効果音のオン/オフも音量も一切変えられない。`audio.js` の全音声を1本のマスター `GainNode` に通し、スタート画面のつまみ＋試合中のキー（例：M）で操作できるようにする。設定は localStorage に残す。
- [ ] M 一時停止とメニューへ戻る（Esc） — いま試合を始めると、リロードする以外に止める・難易度を変え直す・やり直す手段がない（`Game#start()` は `started` で二度目を弾き、セットが終わると自動で次の試合が始まり続ける）。Esc で進行を止め、「再開／このセットを棄権してスタート画面へ」を出す。`main.js` が `game.update()` を呼ばないだけで止まる作りなので、スタッツ画面と同じ仕組みで足せる。
- [ ] M 設定を localStorage に保存する — 難易度・サーフェス・プレースタイル・ガイド・必殺技の選択、そして**4人×10項目の能力値**が毎回リセットされる。選手設定はいちばん手間がかかるのに毎回入れ直しになっている。`file://` でも動くよう try/catch で包み、読めないときは現在の既定にそのまま倒す。
- [ ] M 試合形式を選べるようにする — いまは1セット6ゲーム先取に固定（`RULES`）。ノーアド（デュースを1本勝負に）、8ゲームプロセット、タイブレークのみの短い試合、を選べるようにする。`scoring.js` はほぼ `RULES` を読むだけなので、設定を増やす形で入る。短い試合形式があると1回の起動で完結しやすい。
- [ ] M 左利きの選手を作れるようにする — `RACKET_SIDE`（game.js）と `HAND`（scene/player.js）はすでに1箇所に集約されているので、選手ごとの値にすれば左利きが作れる。フォア／バックの向きが相手ごとに変わるので、配球の駆け引きが増える（`buggyCurveSign()` も選手ごとに正しく鏡になる）。
- [ ] L チャレンジ（ホークアイ）— ライン際のコールに対して1セット3回まで異議を申し立て、スローのリプレイとボールマークで判定を見せる。`bounce()` は既に**本当の接地座標**を持っていて（`groundCrossing()`）、`COURT.LINE_SLACK` という「ぎりぎり」の幅も、`trail` という軌跡も、リプレイの仕組みもある。いちばんテニスらしい演出が、いちばん既存の部品で作れる。まず「ライン際（`LINE_SLACK` 圏内）だったポイントを記録して、リプレイでボールマークを出す」だけを `M` に切り出せる。
- [ ] L スマートフォン対応 — いまはスタート画面までしか操作できない（README 記載）。画面下に仮想スティック＋スイングボタンを重ね、`input.js` に touch の経路を足す。`moveX`/`moveZ`/`lob`/溜めという入力の窓口はすでに小さくまとまっているので、`Input` クラスの中で完結できる。
