# ROADMAP

`/evolve` skill（`.claude/skills/evolve/SKILL.md`）がこのファイルを読んで、1サイクルにつき1項目だけ拾って実装する。
完了した項目は [docs/roadmap-done.md](./roadmap-done.md) に移す。

## 書式

```
- [ ] <サイズ> <タイトル> — <補足・受け入れ条件>
```

- **サイズ**は `S`（1サイクルで確実に終わる小さな修正）／`M`（1サイクルで終わるが設計判断を伴う）／`L`（複数サイクルにまたがる、または着手前に方針を相談すべき大きな機能）。
- `/evolve` は **`S` と `M` だけを自動で拾う**。`L` は拾わない（人間がサイズを分解して `S`/`M` に落とすか、方針を決めてから着手する）。
- 優先度は上から順。追加するときは狙う位置に挿入する（末尾ではなく）。

## 未着手

### バグ（実測で再現を確認したもの）

- [ ] S CPU/AI の反応遅延がサーブのたびに素通りする — `updateReactTimers()` は `ball.last` が**前フレームから変わった瞬間**にだけ反応遅延を仕掛けるが、`lastBallOwnerSeen` は `phase !== 'rally'` の間も毎フレーム更新される。`beginServe()` は `ball.last` を前のポイントのまま残すので、**「前のポイントで最後に打ったチーム」＝「次のサーバー」のときだけ owner が変化せず、レシーブ側の `reactTimers` が 0 のまま**になる（実測：シングルスで人間が自分のミス／ウィナーでポイントを終えた次の自分のサーブでは `reactTimers.cpu` が 0.115 → 0.000。ダブルスの `youMate` も同じ）。自分のサービスゲームの多くで CPU がノータイムでリターンに動き出していることになる。受け入れ条件：前のポイントの最後の打者が誰であっても、サーブが打たれた瞬間にレシーブ側へ `PLAYER.CPU_REACT × attr.react` が必ず入る（`beginServe()` で `ball.last` を消す／`serve()` から明示的に仕掛ける等）。回帰テストを両方のケースで置く。
- [ ] S 溜めキーを押したまま次のポイントに入るとテイクバックが効かない — `tickCharge()` はポイントが決まった瞬間（`phase==='over'`）に `charging=false` にするが、キーは物理的に押されたままなので keydown が二度と来ない＝`chargeStart()` が呼ばれない。次のポイントで構えが出ず、離しても `chargeRelease()` が素通りする（実測で確認）。同じ理由で**フォールトのコール中（`phase==='fault'`）に押し直しても無効**——`chargeStart()` が `phase==='serve'` しか見ていないため、README が約束している「1本目がフォールトしても押したまま2本目を待てる」は*フォールト前から押していた場合しか*成立しない。受け入れ条件：キーを押しっぱなしのままポイントをまたいでも、次のサーブ待ちに入った時点で構えが復帰する（`input.js` が phase 遷移で押下状態を再送するか、`chargeStart()` を `'over'`/`'fault'` でも受け付けて `tickCharge()` 側で保留する）。
- [ ] S `predictLanding()` の着地点が実際の着地点より常に進行方向へ行き過ぎる — `reflectBounce()` は `groundCrossing()` で本当の接地点へ補間するのに、`predictLanding()`／`predictApex()`／`predictBounceApex()` は**1コマ進めた後の座標をそのまま返す**。刻みが 1/120 秒なので速い球ほど進行方向へ行き過ぎ、実測で平均 8cm・最大 34cm、しかも常に外側へ偏る。`ai.chaseTarget()` の追跡目標と `dashUnreachable()`（縮地を出すかの判定）がこのぶんずれている。受け入れ条件：着地として返す座標を `groundCrossing()` 相当で補間し、`PHYSICS.STEP` 刻みの実物理と数 cm 以内で一致する（テストで差を測る）。

### 表示・ドキュメントのズレ

- [ ] S 存在しない「着地マーカー」への参照を消す — `README.md` の構成表（`ball.js ボール・影・着地マーカー`）と `physics.js` の `predictLanding()` のコメント2箇所が、実際には実装されていない着地マーカーを指している（`scene/` に該当コードなし）。消すか、本当に作るかを決める。
- [ ] S スタッツ画面の「必殺技」行のコメントが古い — `hud.js` の `STAT_ROWS` に「CPU/AI は使わないので常に0」とあるが、Hard では AI も技を使う（`SPECIAL.AI`）。動作（両方0のときだけ行を隠す）は正しいのでコメントだけ直す。
- [ ] S スタート画面の「シングルス<kbd>Space</kbd>」が実際の動作と違う — Space は「**いま選ばれている**形式で開始」なので、マウスでダブルスを選んでから Space を押すとダブルスで始まる。D にも「ダブルスを選んでそのまま開始」しかなく、キーボードだけでシングルスへ戻す手段がない。ラベルを開始キーの側へ移すか、シングルス選択キーを足す。
- [ ] S Hard の AI の必殺技の残り回数が画面に出ない — `hud.setSpecialUses()` は人間の `game.specialUses` しか見ておらず、AI が技ごとに独立した回数を持っている（`actor.specialUses`）ことが分からない。相手が鷹の目を使い切ったかどうかは駆け引きの材料になるので、スコアボード側に相手ぶんも小さく出す。

### 追加したい機能

- [ ] M 音量調整とミュート — 効果音のオン/オフも音量も一切変えられない。`audio.js` の全音声を1本のマスター `GainNode` に通し、スタート画面のつまみ＋試合中のキー（例：M）で操作できるようにする。設定は localStorage に残す。
- [ ] M 一時停止とメニューへ戻る（Esc） — いま試合を始めると、リロードする以外に止める・難易度を変え直す・やり直す手段がない（`Game#start()` は `started` で二度目を弾き、セットが終わると自動で次の試合が始まり続ける）。Esc で進行を止め、「再開／このセットを棄権してスタート画面へ」を出す。`main.js` が `game.update()` を呼ばないだけで止まる作りなので、スタッツ画面と同じ仕組みで足せる。
- [ ] M 設定を localStorage に保存する — 難易度・サーフェス・プレースタイル・ガイド・必殺技の選択、そして**4人×10項目の能力値**が毎回リセットされる。選手設定はいちばん手間がかかるのに毎回入れ直しになっている。`file://` でも動くよう try/catch で包み、読めないときは現在の既定にそのまま倒す。
- [ ] M ブレークポイント／ゲームポイントのコール — `scoring.js` は既にポイント状況を全部持っているので、「ブレークポイント」「ゲームポイント」「セットポイント」を判定してコールと歓声に乗せられる。1セットマッチの緊張感が一段上がるわりに、既存の `hooks.call` と `sfx.point` にそのまま載る。合わせてスタッツに「ブレークポイント 3/5」を足す。
- [ ] M 試合形式を選べるようにする — いまは1セット6ゲーム先取に固定（`RULES`）。ノーアド（デュースを1本勝負に）、8ゲームプロセット、タイブレークのみの短い試合、を選べるようにする。`scoring.js` はほぼ `RULES` を読むだけなので、設定を増やす形で入る。短い試合形式があると1回の起動で完結しやすい。
- [ ] M 練習モード（サーブ練習／ラリー練習） — 得点をつけず、サーブなら着地点とフォールト率が出る／ラリーなら CPU が同じ球を出し続ける、という反復練習のモード。溜めゲージの線・ガイド・スマッシュの先回り印という既存の「教える仕掛け」が、実戦だと1ポイントに1回しか試せないので活ききっていない。
- [ ] M 左利きの選手を作れるようにする — `RACKET_SIDE`（game.js）と `HAND`（scene/player.js）はすでに1箇所に集約されているので、選手ごとの値にすれば左利きが作れる。フォア／バックの向きが相手ごとに変わるので、配球の駆け引きが増える（`buggyCurveSign()` も選手ごとに正しく鏡になる）。
- [ ] L チャレンジ（ホークアイ）— ライン際のコールに対して1セット3回まで異議を申し立て、スローのリプレイとボールマークで判定を見せる。`bounce()` は既に**本当の接地座標**を持っていて（`groundCrossing()`）、`COURT.LINE_SLACK` という「ぎりぎり」の幅も、`trail` という軌跡も、リプレイの仕組みもある。いちばんテニスらしい演出が、いちばん既存の部品で作れる。まず「ライン際（`LINE_SLACK` 圏内）だったポイントを記録して、リプレイでボールマークを出す」だけを `M` に切り出せる。
- [ ] L スマートフォン対応 — いまはスタート画面までしか操作できない（README 記載）。画面下に仮想スティック＋スイングボタンを重ね、`input.js` に touch の経路を足す。`moveX`/`moveZ`/`lob`/溜めという入力の窓口はすでに小さくまとまっているので、`Input` クラスの中で完結できる。
