## 2026-08-18 選手の移動アニメーションをリアルにする（歩く/走るモーションブレンド）
- ブランチ: なし（/evolve 経由ではなく、ユーザーからの直接指示で本会話中に実装）
- 実施内容: `src/scene/player.js` の脚を単一円柱から股関節→膝→足先の2関節チェーン×2本（左右）に分解し、`setGaitPose()` で実速度に応じた歩行/走行のプロシージャルアニメーション（腿の振り・膝の曲げ・体幹の上下ゆれ・前傾・逆手のカウンタースイング）を追加。`game.js` の `movePlayers()` に実移動量ベースの `speed` トラッキングを追加し、`config.js` に `GAIT` セクションを新設。既存のラケット腕のスイング（`rotation.y`）とは別軸（`rotation.x`）で独立して動くため干渉しない。素材はWeb由来のものを使わず、完全にプロシージャル（数式ベース）で実装（file:// 単体動作・ビルド不要という制約を維持するため）。
- 既知の制約（意図的なスコープ外、正直に記録）:
  - 真の逆運動学（目標位置からの解析的IK）ではなく、角度を直接生成する簡易版。足が地形に正確に接地する保証はない（現状のコートは平面なので実害はない）。
  - 人間操作の移動はキーボードのオン/オフ入力で常に `PLAYER.SPEED` 一定のため、実際には「静止 ⇔ 走り」しか見えず「歩き」の速度帯はほぼ出現しない。CPU は `CPU_RECOVER`(4.2)/`CPU_CHASE`(6.6) の2速度＋減速時の遷移があるぶん、やや幅広く見える。真に歩く速度を作るには別途「加速・減速・方向転換」（ROADMAP末尾の別項目）の実装が必要。
- テスト: `node tests/smoke.mjs` — ALL PASS。加えて `claude-in-chrome` と headless Chrome（`file://` 直接オープン）でも目視確認（走行時の交互ストライド・膝の曲げ・停止時のニュートラル姿勢への復帰・スイング動作との非干渉、いずれも問題なし。コンソールエラーなし）。
