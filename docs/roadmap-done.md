## 2026-08-26 ネットに出た相手への CPU の攻め手を多様化する
- ブランチ: なし（ユーザー指示によりROADMAPを上から順にmain上で直接実装）
- 実施内容: `ai.js#cpuShot()` は相手が `CPU.NET_Z`(4.0m) 以内にいると、新設の `netPlayShot()` に切り替わるようにした。`netPlayShot()` は「相手が `CPU.NET_PRESS_Z`(1.8m) 以内まで完全に詰め切っている」ときだけロブ率を `NET_LOB_PRESSED`(0.55) まで上げ、そうでなければ `NET_LOB`(0.22) に抑える。ロブでないときは、ネットの近さ（closeness）で「足元へ沈める短い球」（`netDropShot()`）の重みを、相手の中央寄り具合（centered）で「サイドライン際への低く速いパッシング」（`netPassShot()`）の重みを連続的に変え、正規化した確率でどちらかを選ぶ。ベースライン同士のラリー（`opponent.z` が `NET_Z` の外）は従来どおり `LOB_BASE + LOB_VS_STRETCH * stretch` のロジックのまま変更なし。旧 `CPU.LOB_VS_NET` は削除し、代わりに `CPU.NET_PRESS_Z`／`NET_LOB`／`NET_LOB_PRESSED`／`NET_DROP_*`／`NET_PASS_*` を `config.js` に追加。
- テスト: `node tests/smoke.mjs` — ALL PASS（既知の無関係な既存フレーク「the drop lands right behind the net」を除く）。新規テスト（N=400のサンプリング）：人間がネット際（z=-2、中央）にいるとき、ロブ率が旧50%から明確に下がる（<35%）こと、足元・パッシングの両方が一定割合で出ること／完全に詰め切っている（z=-1.3）ときはロブ率がそれより上がること／相手が中央寄りなほどパッシングが増え、サイドに寄り切っているほど減ること／ベースライン同士のラリーはこのロジックの対象外のままであること。既存の「CPU/AIのロブ」テストは新しい設定キー（`NET_LOB_PRESSED`）に合わせて更新。
- 備考: セルフレビューで `NET_PRESS_Z` の値とコメントの整合性について指摘があり、コメントを「PLAYER.Z_NEARに寄せた、NET_Zよりずっと狭い範囲」という表現に修正して明確化した（値自体は受け入れ条件を満たすことを新規テストで確認済みなので変更していない）。

## 2026-08-24 ドロップショットを実装する（弱いスライスでネット際に落とす）
- ブランチ: なし（ユーザー指示によりROADMAPを上から順にmain上で直接実装）
- 実施内容: スライス（C）をほとんど溜めずに離したとき（溜め <= `DROP.MAX_CHARGE`=0.25）だけ、`playerShot()` が通常のグラウンドストロークとは別枠の狙いを返すようにした：着地はネットから 1.2〜2.4m、左右は 0.8〜2.6m、飛翔 1.15秒、ネットの余裕は `DROP.CLEARANCE`=0.12（通常は0.30）。余裕を詰めないと `solveShot()` のネット回避ループが滞空を伸ばしてしまい、ただの浅い山なりになる。`playerShot()` が `clearance` を返すのはこの球種だけで、他は従来どおり既定値を使う。
  - **バウンドを殺す**: 最初の実装（スピンは 'slice' のまま）ではネット際に落ちても2バウンド目まで8m以上転がってしまい、「ただの浅い球」にしか見えなかった。原因はスライスの水平減衰倍率が `1.05`＝**フラットより滑って伸びる**設定（スライスドライブの持ち味）だったこと。ドロップは逆に前へ進む力を殺すのが持ち味なので、`SPIN` に 'drop' を追加（実効重力はフラットと同じ1、反発 0.45、水平減衰 0.45）し、`playerShot()` が `spin:'drop'` を返して `hit()` がそれを優先する形にした。結果、ベースラインから打った場合の1→2バウンド目の距離が **8.5m→2.0m** になり、ネット際で止まる球になった。
  - 実測（ベースラインから）: ドロップ＝着地 z=2.35m・ネット通過の高さ1.46m（ネット上端1.02m）・2バウンド目 z=4.38m。溜めたスライス＝着地 z=10.03m・2バウンド目 z=24.33m。溜めなしのフラット＝着地 z=5.3m。ミドル（z=-6）から打つと着地 z=2.15m・2バウンド目 z=3.31m とさらに厳しい球になる。
- テスト: `node tests/smoke.mjs` — ALL PASS。新規テスト1件（10アサーション）：溜めなしのスライスが `spin==='drop'` になり `DROP.Z_MIN`〜`Z_MAX` に着地すること（かつネットは越えていること）、溜めたスライスは従来どおり 'slice' のまま深く着地すること、溜めなしでもフラット/トップはドロップにならないこと、ドロップの1→2バウンド目の距離が通常スライスの半分未満でサービスボックス内に収まること。既存の「C＝スライスがグラウンドストロークに反映される」テストは、溜めなしだとドロップになる仕様変更に合わせて溜め量を `DROP.MAX_CHARGE` より上にしてから検証するよう修正。ブラウザ実機（`claude-in-chrome`、ローカル`http.server`経由）で実際に C の keydown/keyup を送り、`spin==='drop'`・着地 (x=-2.48, z=1.30) を確認。CPU がそれを拾って返球するところまで動作した（＝一撃必殺ではなく、相手を前に走らせる戦術になっている）。コンソールエラーなし。
- 備考: 同日の「移動中は溜められない」変更（`CHARGE.MOVE_CAP_FLOOR`=0）との組み合わせで、**走りながら C で打った球は必ずドロップショットになる**。「弱いスライス＝ドロップ」という今回の仕様の素直な帰結だが、意図せずドロップが出るのが煩わしければ `DROP.MAX_CHARGE` を下げるか、走行中は除外する条件を足すのが手。
