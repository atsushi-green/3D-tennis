## 2026-08-21 フォールトを実装する（セカンドサーブ／ダブルフォルト）
- ブランチ: evolve/serve-fault
- 実施内容: これまでは1回のサービス（トス→打つ）がネットまたはアウトになると即座にそのポイントを失っていた。実際のテニスと同じ2本ルールを実装した。`game.js` に `this.serveNumber`（1|2）を追加し、`newPoint()` で毎ポイント1にリセットする。従来 `newPoint()` に直接書かれていたサーブ待ち状態の構築（タイマー・ボールのリセット、サーバー／レシーバー〈ダブルスは両者の相方も〉のスタンス配置、コール表示、`placeServeBall()`）を共通の `beginServe(faultReason)` に切り出し、`newPoint()`（1本目、`faultReason` なし）と新設の `retryServe(reason)`（フォールト後のセカンドサーブ、`faultReason` あり）の両方から呼ぶようにした。`faultReason` が渡されたときはコール文言を「セカンドサーブ」に変え、理由（'ネット'|'アウト'）を添えて表示する。
  フォールト検出は `stepBall()` の `hitsNet()` 分岐と `bounce()` の1バウンド目判定の2箇所に追加した。従来はどちらも無条件で `endPoint()` を呼んでいたが、`this.serveInFlight`（＝サーブがまだ一度も返球されていない）のときだけ新設の `serveFault(reason)` を呼ぶよう分岐させた。`serveFault()` は `serveNumber===1` ならセカンドサーブへ切り替えて `retryServe()`（失点なし、サーバー・レシーバーは変わらない）、`serveNumber===2` なら `endPoint(opponent(this.server), 'ダブルフォルト')` で相手に得点を与える。
  `bounce()` の1バウンド目判定には、サーブ専用の新設メソッド `inServiceBox(ball)` も追加した。従来の `bounce()` はコート全体（サイドライン・ベースライン）でしか着地判定をしておらず、サービスライン（`COURT.SERVICE`）やセンターサービスラインは一切見ていなかった（＝サービスラインより深く着地したサーブも、ボックス幅がシングルスコートの範囲内なら「フォールトではない」と誤って通していた既存のバグ）。`inServiceBox()` はネット〜サービスライン・センターサービスラインより狙った側、という正しいサービスボックスの境界で判定する（ダブルスでもシングルスと同じ幅のまま、という既存の設計方針に合わせた）。
  セルフレビューで指摘された2点を追加修正：①「狙う対角の符号(targetSign)・打ち込む方向(dir)」の式が `serve()`/`beginServe()`/`inServiceBox()` の3箇所に重複していたので、共通の `serveAim(serverTeam, side)` 関数（`opponent()` の直後）に一本化した（`beginServe()` のサーバー立ち位置の式も `-targetSign * SERVE.STANCE_X` に簡潔化）。②ライン判定の許容誤差 `0.03` が `game.js` に複数箇所ハードコードされていた（CLAUDE.mdの「マジックナンバーはconfig.jsに集約」に反する）ので、`config.js` の `COURT.LINE_SLACK` に切り出し、`inServiceBox()` と既存の `bounce()` の全コート判定の両方から使うようにした。

## 2026-08-20 溜めなしの打球をもっと山なりに／CPUが強すぎる問題を修正（反応遅延・ぎりぎりの返球を弱く）
- ブランチ: なし（/evolve 経由ではなく、ユーザーからの直接指示で本会話中に実装）
- 実施内容: ユーザー報告「あまり溜められずに弱く打った時、もっとゆるい山なり気味のボールになるように」「敵の動きが強すぎる。どんなに強いボールをコーナーに打っても余裕で追いつかれて返される。ギリギリなら山なりになったり、逆を突かれたら追いつけないような挙動に」の2点を実装。
  1. **弱打の山なり化**: `SHOT.TAP_T` を `1.02→1.32` に引き上げ、溜めなしショットの滞空時間を伸ばして明確に山なりにした（フル溜め `CHARGE_T=0.44` との差をより体感しやすく）。
  2. **CPUの反応遅延（逆を突かれると間に合わない）**: `Game` に `reactTimers`（cpu/cpuMate/youMate）と `updateReactTimers()` を追加。`ball.last` がチームをまたいで変わった瞬間（＝新しい球が来た瞬間）に、守る側の反応遅延タイマーを `PLAYER.CPU_REACT`(0.18s) にセットし、0になるまで一切移動させない（`moveSinglesCpu()`/`moveDoublesTeams()` を変更）。直前まで別方向へ動いていた/止まっていたところへ逆を突かれると、遅延ぶん出遅れて間に合わなくなる。
  3. **ぎりぎりの返球を弱く**: `hit()` で「打点での実速度(`player.speed`) / `PLAYER.CPU_CHASE`」を `stretch`(0〜1) として算出し、`ai.js` の `shotTarget()` に渡してAIの狙い（深さ・横位置・アウトする確率）を `CPU.STRETCH_*` 系の値へ補間、飛翔時間も `CPU.SHOT_T→CPU.STRETCH_T`（山なり）へ補間するようにした。全力疾走のまま打った＝ぎりぎり追いついた球ほど、浅く・中央寄りで山なりな、ミスもしやすい返球になる。人間の 'you' には影響しない（stretch は常に0）。
- テスト: `node tests/smoke.mjs` — ALL PASS。新規テスト: 溜めなしショットの弾道の頂点がフル溜めの1.5倍以上高いこと、`shotTarget(x,dir,stretch)` が `Math.random` を固定した決定的な条件下で stretch=1 のとき明確に浅く・中央寄りになること（設定値との一致まで検証）、`CPU.STRETCH_T > CPU.SHOT_T` であること、新しい球が来た瞬間に該当する守備側の移動が完全に止まり(`speed===0`)、`PLAYER.CPU_REACT` 経過後に動き出すこと。ブラウザでも同じ挙動（tap弾道の頂点3.62m vs 溜め1.30m、逆を突いた球に対してcpuが反応遅延中は座標が1mmも動かないこと）を確認。3分間のシングルスシミュレーションでもフリーズ・タイマーリーク・コンソールエラーなし。

## 2026-08-20 ダブルスのパートナーAI（youMate）を修正：サーブ前のフットフォルト・レシーブできない・挙動不安定

  2. **レシーブできない／挙動不安定**: `ai.js` の `chasePosition(ball)` が cpu 陣地（z>0）基準の定数（`CPU.CHASE_Z_MIN/MAX/BEHIND`）だけを使っており、常に z>0 の値を返す実装になっていた。`cpu`/`cpuMate` が使う分には問題ないが、`youMate`（you 陣地・z<0）が同じ関数をそのまま使っていたため、自陣に来た球を追おうとすると常にネットの向こう側（cpu 陣地寄りの z≈1.6〜2.1）へ向かってしまい、実際の落下点を追えていなかった。`chasePosition(ball, side)` に `side` 引数を追加（既定 `1`＝従来通り）し、`side=-1` のときは z 方向を鏡映しにする式に変更。`moveDoublesTeams()` の youMate 側の呼び出しだけ `chasePosition(ball, -1)` を渡すようにした。
- 副次的に見つけた点: 上記2つを直した結果、youMate が cpu チームと同等に強くなり、シミュレーションテストで「両チームとも完璧に拾い続けて点が全く決まらない」退行を誘発した（静止したまま延々と Space を叩くだけの非現実的なテスト入力が原因）。テストの入力を実際のプレイに近い「動き続ける人間」に変更して解消（ゲームロジック自体の変更はなし）。
- テスト: `node tests/smoke.mjs` — ALL PASS。新規テスト: `chasePosition(ball, side)` の鏡映し（side=-1 で自陣側に留まること、浅い着地でもネット向こうへ出ないこと）、サーブ待ち中は4人とも（サーバー本人だけでなくレシーブ側の2人も）`newPoint()` のスタンスから動かないこと（you/cpu 両チームのサーブで確認）。ブラウザで実際に youMate をサーバーにして `g.update()` をコマ送りし、CPU_SERVE_DELAY(0.9s) の間スタンスが1mmも動かないこと、その後正常にサーブが発火することを確認。10分間のダブルスシミュレーション（動く人間入力）で youMate のヒット数が cpu 陣営と同程度（同じ試行で cpu 56 / youMate 64 / cpuMate 23 / you 15）になり、フリーズ・タイマーリーク・コンソールエラーなしを確認。
