# Rally One — 3D Tennis

ブラウザで動く3Dテニス。ビルド不要、サーバー不要、ネット接続も不要。

## 動かす

**`index.html` をダブルクリックするだけ。** ブラウザが開いたら Space かクリックで開始。

（three.js は `vendor/three.min.js` に同梱してあるので、オフラインでも動きます）

## 操作

| キー | 動作 |
| --- | --- |
| ←→ | 左右移動 ／ 打つ方向の指定 ／ サーブのコース（T・ボディ・ワイド。ワイド方向へ Shift を押しながら離すと**角度をつけたサービス**＝ワイドより外へ切れるが、その分フォールトもしやすい） |
| ↑↓ | 前後移動 ／ サーブのトス中は着地の深さ（↑＝深く／↓＝浅く） |
| B / V / C | 押しっぱなしでテイクバックを溜め、離すと打つ（B＝フラット／V＝トップスピン／C＝スライス。**Cをほとんど溜めずに離すとドロップショット**＝ネット際に落ちて弾まない短い球になる。押したキーがそのまま結果になり、当たるまで押し続ける必要はない。クリック/タップでも可＝フラット）。サーブは1回目が即トス、トス中の2回目から溜められる。溜め具合は画面下のバーに表示。グラウンドストローク・サーブ以外（スマッシュ・ボレー・CPU/AIの打球）はどのキーでもフラット固定 |
| Shift | ロブ（サーブのトス中はコース選択に使う。上記参照） |
| Q / E | （ダブルス）AIパートナーに前へ詰める／ベースラインまで下がるを指示 |
| D（開始前） | ダブルスで開始（あなた＋AIパートナー vs CPU2人） |
| 1 / 2 / 3（開始前） | CPU/AIの強さを Easy / Normal / Hard から選ぶ（既定は Normal） |
| 4 / 5 / 6（開始前） | コートサーフェスを ハード / クレー / 芝 から選ぶ（既定はハード。選ぶと背後のコートの色もすぐ変わる） |
| 7 / 8 / 9 / 0（開始前） | CPU/AIのプレースタイルを なし / サーブ&ボレー / リトリーバー / ベースライナー から選ぶ（既定はなし。強さとは別軸） |

1セットマッチ（6ゲーム先取、2ゲーム差）。

**スマッシュのチャンスには、先回りすべき地点がコートに出ます。** 高い球（ロブなど）が
来て、それを**ノーバウンドで**打てる高さ（1.8〜2.5m）で捉えられる場所があるとき、そこに
輪のマーカーが出ます（バウンドさせてから打てる球は、立つ位置がベースラインのはるか後ろに
なって決め球にならないので案内しません）。**ベースライン付近（1m以内）に立っている間は出ません** —
そこから打点まで走ると走るだけで滞空時間を使い切ってしまい、どのみち溜めが間に合わないためです。
前に詰めた瞬間から出ます。
輪の中に立って足を止め、溜めてから離せばスマッシュになります。外側の輪は打点までの残り時間で、
内側の輪に重なった瞬間が打つタイミング。色は 水色＝走れば間に合う／黄色＝もう届く位置にいる／
赤＝全力で走っても溜めが間に合わない（スマッシュは諦めて普通に返すほうが安全）。
スマッシュには「高い打点」だけでなく「溜め」も要り、走っている間は溜められないので、
**打点の手前で止まっておく**のがコツです。輪の中で溜めている間はラケットを頭の後ろに担いだ
**振りかぶり**の構えになり、離すと**ジャンプして上から振り下ろす**（着地までがワンモーション）。

**打点のタイミングでもコースが変わります。** ボールを前（遠く）で捉えるほど「引っ張り」、
引きつけて近くで打つほど「流れ」ます。フォアハンドとバックハンドでは体を横切る向きが
逆なので、引っ張る/流れる方向も逆になります。←→ の方向指定と組み合わせて使えます。

## テニスのルール

- サービスサイドはクロス（-1）から始まり、ポイントごとに逆クロス（+1）と交互になる。
- サーブはノーバウンドで打ち返せない（1バウンドしてから返球する）。
- レシーバーはポイント開始時、狙われる対角のボックス付近（レシーブポジション）へ自動で移動する。
- ダブルスでは、サーバーはゲームごとにチームが交代し、各チーム内でも次に自分たちの番が
  来るたびにパートナーと交互になる（実際のルールと同じ）。レシーブするコート（デュース/アド
  相当）は各選手で固定：主力(you/cpu)は+1側、パートナーは-1側を必ず受ける。
- 6ゲーム-6ゲームになったら、通常のゲームの代わりに7ポイント先取・2点差のタイブレークを行い、
  取った方がそのままセット（7-6）を取る。タイブレーク中はスコア表示が0/15/30/40ではなく素点になり、
  サーバーは1本目だけ現在の担当のまま、以降は2ポイントごとに交代する。
- ポイントが決まると、取った側がそのポイントで最後に放ったショットの球種（スマッシュ／ボレー／
  ロブ／ドロップショット／スピンショット／スライスショット／フラットショット／サービス）が
  コールと一緒に出る。相手のネット・アウトで決まった場合は「そのミスを誘った自分の1本」になる。
- CPU/AI の守備範囲は「反応に使える時間」で決まる。打たれてからボールが自分に届くまでが
  短いほど狭くなり、スマッシュや至近距離のボレーは体のすぐ近くしか触れない（ダブルスの前衛が
  スマッシュを高確率で拾ってしまう問題への対策。1バウンドを挟む普通のラリー球は従来どおり）。
- ポイントごとに弱いランダムな横風が吹く（スコアボード下に「風 →0.3」のように表示）。サーブの
  飛翔（トス〜1本目の着地）は無風のまま行われ、返球された瞬間からラリー中の球だけが風に流される。
- サーブを打った瞬間の初速がスコアボード脇に「サーブ 172km/h」のように出る（人間・CPU/AI
  どちらも）。次のポイントが始まるまで表示が残る。
- CPU/AI は、人間がネットに詰めているときにロブ一辺倒にはならず、足元へ沈める短い球・
  サイドライン際へのパッシング・ロブを状況で撃ち分ける。ロブを多めに選ぶのは人間が
  ネットのすぐ近くまで詰め切っているときだけ。
- コートサーフェスを ハード／クレー／芝 から選べる。クレーは高く弾んで減速し（ラリーが
  長引きドロップが効く）、芝は低く滑って伸びる（ネットプレー有利）。ハードは既定の物理と
  完全に一致する。
- CPU/AI にプレースタイルを持たせられる（強さとは別軸）。サーブ&ボレーヤーはサーブ後に
  ネットへ詰め、リトリーバーはミスしにくくよく走りロブを多用し、ベースライナーは
  コースを広く速く突く代わりミスも増える。
- ポイントが決まると、直近の攻防をコート脇の低いアングルからスロー再生する。再生中は
  次のポイントの開始を待ち、何かキーを押せばすぐスキップできる。
- 長いラリーで走るとスタミナが減り、移動速度と（人間の）溜め速度が少し落ちる（スコアボード
  脇に残量バーを表示）。人間・CPU/AI とも同じルールで効き、ポイント間で少し回復する。

## 構成

```
index.html          DOM（HUD とスタート画面）と script の読み込み順
styles/main.css     HUD のスタイル
vendor/three.min.js three.js r128（同梱）
src/
  config.js         寸法・物理・難易度などのチューニング値
  math.js           clamp / rand / approach など
  physics.js        弾道の積分、落下点の予測、初速の逆算（純粋関数）
  scoring.js        ポイント表記とゲーム／セットの成立判定（純粋）
  ai.js             CPU の位置取りと狙い先
  game.js           ルールと状態遷移（three.js にも DOM にも触らない）
  input.js          キーボード／ポインタ入力
  hud.js            スコアボードとコール表示（DOM に触る唯一の場所）
  audio.js          Web Audio による効果音
  scene/
    renderer.js     レンダラー・カメラ・ライト
    court.js        コート面（ラインは CanvasTexture）とスタンド
    net.js          ネットとポスト
    player.js       選手のメッシュとスイングのポーズ
    ball.js         ボール・影・着地マーカー
    hint.js         スマッシュの先回り地点マーカー
    world.js        シーンの組み立てと「状態 → メッシュ」の反映
  main.js           起動点。配線とフレームループだけ
```

各ファイルは即時関数で包まれていて、`window.RallyOne` に自分の分だけを足していきます。
先頭で使うものを分割代入しているので、そこがそのファイルの依存一覧です。

```js
(function (RallyOne) {
  'use strict';
  const { COURT, PHYSICS } = RallyOne.config;  // ← これが import 相当
  ...
  RallyOne.physics = { netHeightAt, ... };     // ← これが export 相当
})(window.RallyOne = window.RallyOne || {});
```

`index.html` の `<script>` は依存順に並んでいるので、**ファイルを追加したらここにも1行足す**こと。

依存の向きは `main → game → (physics / scoring / ai / config)` と `main → scene/*` の二方向で、
ゲームロジック側は three.js も DOM も参照しません（= Node でそのままテストできる）。

## 開発メモ

- コンソールから `RallyOne.game` で現在の状態（ボール、選手、スコア）を覗ける。
- `game.js` は `hooks`（音・コール・スコア更新）を注入される。表示を変えたいときはここを差し替える。
- 難易度は `config.js` の `CPU` と `PLAYER` を触る。
- ポイント間の待ち時間は `setTimeout` ではなくゲームループ内のタイマー（`Game#after`）で数えているので、
  ポイントがリセットされると必ず破棄される。
- ES モジュール（`import`/`export`）は使っていない。`file://` で開けなくなるため。
- ロジック層の回帰テストは `node tests/smoke.mjs`。three.js も DOM も使わず、Node だけで検証する。
- タスクのバックログは [docs/ROADMAP.md](./docs/ROADMAP.md)。`/loop 2h /evolve` のように定期実行すると、
  そこから1件ずつ拾って実装・テスト・コミットする（詳細は [.claude/skills/evolve/SKILL.md](./.claude/skills/evolve/SKILL.md)）。
